# Receivables finance portfolio surveillance (PRIVATE)

Private design record. The construction is generated by solution/generate.py with the six lane estimators in solution/estimators.py.

This file is oracle-only. It never enters the agent work image. The judge image carries the graded truth at tests/hidden/truth.jsonl and the scorer; it carries neither this file, nor the estimators, nor the floor-setting portfolio.

## What is graded

Six lanes, equal weight, purely additive, with no global gate and no consistency veto. Every graded value is the deterministic output of the private estimators in solution/estimators.py applied to the published inputs under the ledger discipline below. No realised random draw is graded anywhere, so full credit is reachable in principle and the aggregate is not bounded by outcome noise. The oracle solution/solve.sh recomputes the truth from the public workspace and never copies it.

## The ledger discipline

Training rows
A record at period q is fitted on closed rows with booked_period strictly before q. Each closed row enters with the values the ledger carried at q: a row whose restated_period is at or after q enters with its as_booked values, and a row whose restatement was already known at q enters with its corrected top-level values. The manual documents the fields and never states which version the desk uses; the published history is consistent only with this point-in-time reading. A solver that fits on corrected values throughout is fitting a ledger the desk never saw.

## The structural property this construction carries

Each lane carries its own fitted estimator over its own data view. Shared code is transport only. No lane consumes another lane's estimator output and no estimator calls another; solution/measure.py verifies this by walking the estimator module's syntax tree and by a deletion ablation. The six methods are deliberately from six different families: local linear regression, accelerated-time survival warping, ridge logistic regression with a prevalence-matched threshold, kernel regression with cohort quartiles, ridge regression with a robust residual kernel, and a two-part empirical-Bayes severity model.

## Regime break

Closed-case levels shift at period 14: dilution rises, collections slow, escalations and losses rise, availability falls. The history periods [8, 10, 12] precede the break and the query periods [16, 20] follow it, so a method that treats the history as a labelled training set is calibrated to a regime the graded records no longer sit in. The private estimators refit at every record period with recency weighting, so the truth tracks the break.

## Floors

Each lane's floor is the measured maximum over a frozen portfolio: cheap methods, a complete set of degenerate controls, a distribution-derived envelope optimised over error breakpoints for the currency lanes and over the full simplex for the collection lane, and two one-shot competent tiers, one fitted to the history labels and one fitted naively to the closed cases at their corrected values. A one-shot member is dropped from a lane's floor only where it would leave less than a 0.10 payable range, and every such exclusion is recorded in solution/floors.json. The competent public reference in solution/public_reference.py never sets a floor; it measures what an informed first attempt earns.

### Floor reproducibility, stated rather than hidden

The floors in `tests/scoring/scorer_manifest.json` are frozen constants and grading reads only those constants, so scoring is deterministic for every submission. The record in `solution/floors.json` is bound to the delivered files: all eight recorded source hashes match the shipped bytes, including `solution/estimators.py` at sha256 `f01e8e9c9bb19e74bcc3da4319a927ab78b9d0a1bb782b6caa03aeaee67fc8ee`.

An earlier revision of this bundle recorded a stale hash for `solution/estimators.py`, because the oracle was edited after the floor measurement was frozen. The record was refreshed by re-running `solution/measure_floors.py` against the delivered files under the pinned stack (numpy 2.1.3, scipy 1.14.1, pandas 2.2.3, scikit-learn 1.5.2). The regenerated `tests/scoring/scorer_manifest.json` is byte-identical to the previously shipped manifest at sha256 `744462876e21b7fb8be564bffaca3a7d36c56eb9035441588ada572ce1aad679`, and every one of the six per-lane floor values is unchanged to the last bit, so the refresh carries no scoring consequence. `estimators.py` is the module the oracle executes and it is not a floor setter; `measure_floors.py` runs it only to assert that the oracle recomputes the frozen truth byte for byte, which that run re-asserted.

The oracle was verified independently in the same run and by a full Harbor trial: it scores exactly 1.0 and an untouched environment scores 0.0. The workspace-access audit recorded 802 reads over 802 unique paths for the one-shot tier and 782 over 782 for the cheap tier, with no violations.
